# 工位交接提示

所有工位先读任务单，再核对输入文件和 hash。不得修改其他工位拥有的最终证据；应另写修订和问题列表。

## 资料发现

输入：建筑名、城市、版本、展示范围。用可用的真实检索工具研究，先核实建筑实体，再找正面、斜侧面/俯视和关键细部。输出 sources.json：URL、标题、访问时间、来源等级、视角、实际观察、引用定位、素材使用范围，以及不足。无需下载公开照片来绕过展示限制。每个参考必须真正打开或看过；不要仅凭搜索摘要宣称观察了建筑。资料找齐后通知规划工位；不能替它生成虚构尺寸。

## 建筑规划

输入：来源包与参考图。识别轮廓、层数/檐数、屋顶形制、台基、柱网和比例。输出 model-plan.json 与镜头脚本。将真实受力体系、表面材质和艺术装配顺序分开。每个关键参数说明来源或艺术选择。先指定各构件组的支承对象，再安排起落时序。

## 施工

输入：冻结的来源与模型计划。使用 vendor/architecture-skill/SKILL.md。每个建筑独立 adapter；先完成最终轮廓，再完成确定性装配、拆解表现、材质和镜头。保留单一 progress、颜色/阴影一致、固定 seed、资源释放和状态接口。输出可运行源代码、构建/检查结果、代表截图及剩余限制。

## 独立检查

审查者不得是该项施工的作者。技术检查验证数值、时序、重建/回退一致性和浏览器实际渲染；视觉检查查看成品正面、斜侧与关键细部，逐项对照真实参考；视频检查打开实际 MP4 并查看采样帧。每个结论绑定具体工件 hash，问题包含 ID、严重度和修复位置。未查看的内容记 UNKNOWN。TITMAS 只通过登记并验证的真实适配器接入，其回执与本地视觉审查分开。

## 出片

输入：建筑 adapter、镜头脚本、目标画幅、已记录检查状态。使用固定 frame index 计算 progress 与相机，不依赖实时 rAF 录屏速度。渲染前后源文件 hash 必须相同，检查同一帧重复结果、浏览器错误、ffprobe 的帧率/尺寸/时长与首中末画面。封面来自本次渲染。把静音、预览规格和任何未过门禁写入交付说明。

## 总指挥复核

读取所有工位输出和 CLI 的阻塞清单，确认问题关闭的是同一版本。最终向用户展示视频与最关键限制，区分“可以看预览”与“通过全部检查”。向驾驶舱写本项目状态引用，不改写 TITMAS、Scout 或其他项目的事实和准入状态。
