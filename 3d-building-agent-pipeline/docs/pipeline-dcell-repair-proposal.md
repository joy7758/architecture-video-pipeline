状态：`PROPOSED_LOCAL_PIPELINE_REPAIR`。这是应用层改造方案；尚未实现或激活 DCell 运行能力。

## 目标和范围

修正整条流水线，使参考遗漏、错误继承 PASS、跨任务证据混用、Skill 升级后沿用旧结果等失误能够被发现和阻断。鹳雀楼是已知失败的回归案例，不作为框架中的专属规则。建筑外观和呈现质量仍须对真实工件进行独立审查。

本轮优先改任务协议、依赖关系、检查状态与返工调度；几何修改是使用修正后流水线的后续任务。继续复用现有 CLI、快照器、导出器和指定 Skill，保持 Hailey MIT 署名。驾驶舱承担规范和进展记录；本应用执行本地工作流；TITMAS 按真实接入能力检查证据。

## 三层分离

| 层 | 所有建筑共用的内容 | 可变内容 |
|---|---|---|
| 通用控制层 | 任务身份、版本、输入冻结、依赖、状态迁移、证据校验、问题与返工、回执 | 不包含任何建筑尺寸或形制 |
| 领域检查配置 | 建筑外观、演示表现、视频技术、证据链检查的结构 | 对应建筑类型的必查特征，以及具体参考效果 |
| 建筑任务与适配器 | 使用共同接口接入发现、规划、施工、检查、出片 | 照片、资料、纠错、参数、构件、镜头 |

鹳雀楼的抱厦、四檐等进入其任务配置；其他建筑不继承这些要求。用户选择的 Skill 保持独立依赖，通过施工模块调用。

## 工位合同

发现、规划、施工、视觉审查、技术检查、出片交付各有稳定 ID 和版本。TITMAS 作为外部证据接口单独登记。每份模块合同覆盖规范的全部最小字段，同时向使用者显示简洁中文说明：

- 谁运行、版本是什么、能做什么、明确不承担什么；
- 必需输入及其版本、可接受状态、来源范围；
- 输出工件、检查义务、失败原因；
- 可执行动作、外部副作用、数据保留；
- 升级、替换、撤销和回滚方式，以及已知限制。

每次运行记录 `job_id`、`attempt_id`、`module_id/version`、任务合同版本、组合摘要、输入摘要、输出摘要和实际执行证据。完成执行和通过验收分开表示。审查者身份来自运行记录及工位分配，不仅凭手写 reviewer 字符串认定独立性。

## 必须实现的防错机制

1. **完整参考冻结**：绑定建筑身份、所有当前资料及纠错、Skill 版本、演示视频、特征要求与镜头目标。关键依据无法定位时进入待补资料，不以两个不同图片哈希代表资料充分。
2. **事实到工件的对应关系**：关键特征关联来源位置、预期关系、模型参数/部件、必需视图和观察结论。未标定照片不产生伪精确尺寸误差；未知项保留 UNKNOWN。
3. **依赖图与失效传播**：`USER_CORRECTION`、`REFERENCE_CHANGED`、`SKILL_CHANGED`、`MODEL_CHANGED`、`SHOT_CHANGED`、`REVIEW_REJECTED` 等事件使受影响下游结果变为 STALE。保留无关结果及历史记录，按受影响工位返工。
4. **真实范围的验收**：建筑保真、演示匹配、技术、TITMAS 证据分别记录 PASS/FAIL/UNKNOWN/NOT_RUN；过期另标 STALE。必需项未通过、存在未关闭关键问题或当前用户否定时，交付不能就绪。
5. **组合重验**：升级 Skill、换模型适配器、换视觉工位、回滚组件，都产生新的组合记录。不得因某组件历史 PASS 而批准新组合。
6. **问题关闭证据**：每个问题有稳定 ID、影响范围、证据和修复验收条件。新结果绑定具体版本，独立复核后关闭；修改说明本身不是关闭依据。
7. **回执角色清晰**：文件哈希证明对应字节；视觉审查判断内容；TITMAS 检查它真实支持的合同与回执。三者结论不能相互替代。

例如，用户更新屋顶参考后，相关规划、模型保真结论和成片验收失效；旧视频及其编码检测作为历史事实保留。只有镜头变化时，已有建筑几何检查在依赖未变时可保留，但视频构图、实际视频技术检查和交付检查重跑。

## 实施批次

### P0：堵住已证实的错误通过路径

升级任务与检查合同；拆开四类门禁；加入当前纠错、未关闭问题和 STALE 判断；禁止空白视觉依据签发 PASS。迁移旧任务时保留旧回执，并标注旧范围不足。完善 `pipeline/lib.mjs`、机器 schema、CLI 状态与交接输出。

### P1：让每次工位交接有版本和依赖

实现能力模块登记、运行记录、完整参考冻结、依赖图和事件失效传播。扩展现有快照/出片记录，让“为什么生成”和“实际生成什么”能够相互追溯。总指挥能够解释返回哪个工位、哪些结果可以复用。

### P2：用失败案例和跨建筑任务检验

把鹳雀楼本次故障写成回归负例；再选择一座形制不同的建筑，从发现层走到预览，验证共享控制层不依赖鹳雀楼参数。合成协议测试和真实视觉试验分开报告。通过通用流程后，再使用该流程修复鹳雀楼模型并重新出片。

## 流水线完成标准

- 原资料被更换、纠错被遗漏或用户否定后，旧 PASS 不能继续放行。
- 跨建筑、跨任务、跨版本的证据错误绑定会被拒绝。
- Skill、镜头、适配器和审查工位变更后，准确失效对应下游检查。
- 回滚或撤销不会把旧失败抹掉，也不会自动恢复过期通过。
- 未执行 TITMAS 不能伪装为已执行；技术通过不能覆盖视觉失败。
- 正常任务能继续流转，局部返工只重跑受影响工位；同时验证避免误放行和避免无谓全量重跑。
- 至少完成鹳雀楼真实失败回归和另一座建筑的独立端到端预览，证据与结果如实记录。
- 最终报告分别说明控制机制验证程度和视觉输出质量；不承诺任何建筑都不会出现新的建模错误。
